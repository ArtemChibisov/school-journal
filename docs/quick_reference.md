## 4. Команды: локально

Запустить сайт:

```bash
./.venv/Scripts/python.exe manage.py runserver
```

Остановить — `Ctrl+C` в терминале.

Прогнать все тесты:

```bash
./.venv/Scripts/python.exe manage.py test
```

Тесты одного приложения:

```bash
./.venv/Scripts/python.exe manage.py test school_years
```

Применить изменения моделей к локальной базе:

```bash
./.venv/Scripts/python.exe manage.py migrate
```

Сменить пароль пользователю:

```bash
./.venv/Scripts/python.exe manage.py changepassword artchibisov
```

Перевести журналы из xlsx в Google-таблицы (сначала всегда с `--dry-run`):

```bash
./.venv/Scripts/python.exe manage.py convert_drive_to_sheets --dry-run
```

## 5. Команды: выкатка

Главное правило: **попадание в `main` автоматически обновляет боевой сервер школы.** Поэтому напрямую
в `main` не пишем никогда.

Порядок одной задачи:

```bash
git switch -c название-задачи
```

```bash
./.venv/Scripts/python.exe manage.py test
```

```bash
git push -u origin название-задачи
```

```bash
gh pr create --fill
```

```bash
gh pr checks --watch
```

```bash
gh pr merge --squash --delete-branch
```

Слияние — и есть выкатка. Отдельной команды деплоя нет.

Посмотреть, как прошло:

```bash
gh run list --limit 5
```

Нужны две зелёные галочки: `CI` и `Deploy`. Если что-то упало:

```bash
gh run view --log-failed
```

## 6. Что происходит при выкатке

GitHub заходит на сервер по ssh и делает:

1. `git pull` в `/home/deploy/school-journal`
2. проверяет, что конфиг на месте и служба `scheduler` в нём есть
3. `docker compose up -d --build` — пересобирает и поднимает контейнеры
4. показывает статусы и последние 100 строк логов
5. дёргает адрес живости и ждёт ответа

Если health check не ответил — выкатка считается упавшей.

## 7. Команды: сервер

Зайти:

```bash
ssh deploy@169.58.83.125
```

Дальше все команды выполняются **в папке проекта**, иначе docker не найдёт конфиг:

```bash
cd /home/deploy/school-journal
```

Что сейчас запущено:

```bash
docker compose -f docker-compose.server.yml ps
```

Логи приложения:

```bash
docker compose -f docker-compose.server.yml logs --tail=100 web
```

Логи планировщика:

```bash
docker compose -f docker-compose.server.yml logs --tail=100 scheduler
```

Проверить, что сайт жив:

```bash
curl -fsS https://reports.projector-school.info/healthz
```

Перезапустить только наше приложение:

```bash
docker compose -f docker-compose.server.yml restart web
```

**Перед любыми правками конфигов сервера** — бэкап:

```bash
/usr/local/bin/backup-all.sh
```

## 8. Правила работы с сервером

Сервер школьный, на нём живут чужие сервисы. Нарушение любого пункта ломает не нас.

1. Мы только добавляем своё. Чужие контейнеры не останавливаем.
2. Порты 80 и 443 не занимаем — они у Caddy.
3. Домены других сервисов не трогаем.
4. Перед правкой `/etc/caddy/Caddyfile` делаем бэкап.
5. После перезагрузки Caddy проверяем, что соседние сайты живы.
6. Docker volumes не удаляем — это чужие данные.
7. Секреты живут в `.env.production` на сервере и в GitHub Secrets. В репозиторий не попадают.

Откат конфига Caddy лежит на сервере: `/etc/caddy/Caddyfile.before-reports`.

## 9. Если сломалось

**Порядок действий по убыванию удобства.**

1. **Журнал событий** на сайте, `/logs/`. Там ошибки человеческим текстом, а под каждой — технические
   подробности. Девять раз из десяти ответ здесь, и на сервер заходить не надо.
2. **Запуски**, `/runs/` — если надо посмотреть конкретную задачу целиком.
3. **Логи контейнера** на сервере — если приложение вообще не отвечает.

Типичные случаи:

| Симптом | Где смотреть |
| --- | --- |
| Кнопка отработала, но результат пустой | Журнал событий, фильтр по задаче |
| «Нет доступа к таблице» | Google-подключение → Проверить доступы |
| Сайт не открывается | `docker compose ps` на сервере, затем логи `web` |
| Выкатка упала | `gh run view --log-failed` |
| Не приходят сообщения в Telegram | Журнал событий, фильтр по задаче с напоминаниями |

## 10. Что помнить про данные

- **Локальная база пустая.** Все настоящие данные на сервере. Локально проверяется код, а не данные.
- **Ссылки года — единственный источник.** Всё остальное система берёт по ним. Меняются на экране
  «Учебный год», в одном месте.
- **Журналы модуля 1 заведены руками.** Система их нашла и привязала, но не создавала.
- **Мост к старому слою.** Найденные журналы записываются в `journal_links`, иначе старые проверки
  их не увидят. Подробнее — раздел 2A в [execution_plan.md](execution_plan.md).
