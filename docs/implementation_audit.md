# Аудит реализации и план проверки

Дата аудита: 19.09.2026.

Основание: саммари встречи с заказчиком от 31.08.2026 и `docs/requirements_delta_2026_08_31.md`.

Цель: отделить то, что уже написано и требует только проверки, от того, что надо писать с нуля.

## Как проверялось

Аудит сделан по исходному коду, а не по документации:

- модели всех приложений;
- management-команды;
- HTTP-маршруты `admin_panel/urls.py`, `journal_links/urls.py`, `pipeline/urls.py`;
- типы задач `JobRun.job_type`, встречающиеся в коде;
- прогон `manage.py check`, `manage.py makemigrations --check`, `manage.py test school_years journal_links validation`.

Утверждение «реализовано» в этом документе означает «код существует и подключён к UI или команде». Оно не означает «проверено на реальных данных»: для этого есть раздел «План проверки».

## 3. Найденные дефекты

### 3.1 Преподаватель получает только одну ошибку вместо десяти

Файл: `notifications/reminders.py`, функция `_build_teacher_message`.

Тело цикла по `invalid_entries` содержит только присваивание `suggestion`. Формирование строки сообщения находится за пределами цикла, поэтому в сообщение попадает единственный невалидный критерий - последний по порядку, - хотя заголовок обещает до `TOP_INVALID_CRITERIA_LIMIT`, то есть до десяти.

Влияние: прямо на требование заказчика «преподавателю приходит сообщение, что именно заполнено неправильно».

Приоритет: высокий, правка на несколько строк.

Статус: исправлено. Добавлен тест `test_message_lists_every_invalid_criterion`.

### 3.2 Файл токена `rt.json` не закрыт `.gitignore`

Переименование `token.json` в `rt.json` в незакоммиченных изменениях покрыто правилом `creds/**/*.json` только для пути внутри `creds`. Пути `rt.json` и `school_journal-main/rt.json` не игнорируются, а `school_journal-main/google_oauth_downloader.py` по умолчанию пишет токен именно туда.

Приоритет: высокий, риск утечки refresh-токена в репозиторий.

Статус: исправлено. В `.gitignore` добавлены правила `rt.json` и `**/rt.json`.

### 3.3 Переименование токена не доведено до конца

`school_journal-main/drive_uploader.py` в одном списке путей содержит и `token.json`, и `rt.json`. Файлы `.env.example`, `.env.production.example`, `README.md`, `docs/deployment_guide.md`, `docs/google_report.md` по-прежнему описывают `token.json`, что противоречит новым значениям в compose-файлах.

Статус: исправлено. Все перечисленные файлы приведены к `rt.json`.

Приоритет: средний.

### 3.4 Деплой сломает Google-интеграцию на сервере

В production-томе лежит `/app/creds/google/token.json`. После деплоя приложение будет искать `rt.json`. Требуется fallback в коде или переименование файла на сервере до деплоя.

Приоритет: был блокирующим для деплоя.

Статус: снят. Деплой переезжает на сервер `169.58.83.125` с чистым томом учётных данных, поэтому конфликта имён там нет. Старый сервер `195.54.178.243` остаётся на старом репозитории и больше не получает обновлений.

### 3.5 `school_years` не попадает в CI

Оба workflow прогоняют `journal_links jobs pipeline validation notifications`. Приложение `school_years` с 42 тестами в прогон не включено.

Статус: исправлено. `school_years` добавлен в прогон обоих workflow.

Приоритет: средний.

### 3.6 Приложение не закоммичено, но подключено

`school_years/` не отслеживается git, при этом `admin_panel/settings.py` уже содержит его в `INSTALLED_APPS` и этот файл отслеживается. Коммит только отслеживаемых файлов приведёт к падению проекта на старте.

Приоритет: блокирующий для коммита.

## 4. План проверки

Проверка разбита на три уровня. Первый можно пройти прямо сейчас, второй требует тестового Google-окружения, третий - участия заказчика.

### Уровень 1. Локальная проверка без Google

Не требует кредов, выполняется за несколько минут.

| Шаг | Команда | Ожидаемый результат |
| --- | --- | --- |
| 1.1 | `.\.venv\Scripts\python.exe manage.py check` | Нет замечаний |
| 1.2 | `.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run` | Нет незафиксированных изменений моделей |
| 1.3 | `.\.venv\Scripts\python.exe manage.py test` | Весь набор тестов проходит |
| 1.4 | `.\.venv\Scripts\python.exe manage.py setup_rbac_roles` | Созданы группы `admin`, `vice_principal`, `operator` |
| 1.5 | `.\.venv\Scripts\python.exe manage.py runserver` и обход разделов | Открываются: классы и таблицы, отчёт заполненности, отчёты на проверку, таблица критериев, AI-вычитка, whitelist, контакты родителей, запуски, мониторинг |
| 1.6 | `curl http://127.0.0.1:8000/healthz` и `/readyz` | `ok` и `ok` |
| 1.7 | Вход под пользователем из группы `vice_principal` | Не видны разделы, требующие прав администратора |

Отдельно проверяется дефект 3.1: тест на то, что в сообщение преподавателю попадают все невалидные критерии, а не один. Сейчас такого теста нет.

### Уровень 2. Проверка на тестовом Google-окружении

Требует OAuth-аккаунта с доступом к тестовым папкам и таблицам.

| Шаг | Что проверяем | Как |
| --- | --- | --- |
| 2.1 | Подключение Google | Кнопка `Подключить Google` на странице классов, статус токена становится готовым |
| 2.2 | Скачивание таблицы класса | Запуск проверки дескрипторов и критериев по одной ссылке, задача завершается успешно |
| 2.3 | Корректность разбора листа | В отчёте заполненности предметы, преподаватели и лейблы соответствуют реальной таблице |
| 2.4 | Проверка значений | Намеренно внести в тестовую таблицу неверный уровень, балл выше 100, нераспознанное значение пересдачи; убедиться, что `run_validation` выдаёт соответствующие коды |
| 2.5 | Google-таблица мониторинга | Настроить цель и убедиться, что лист перезаписывается теми же данными, что на экране |
| 2.6 | Telegram | Выдать приглашение преподавателю, получить сообщение, отправить напоминание кнопкой |
| 2.7 | Генерация DOCX | Экран `Отчёты на проверку`, один класс, проверить содержимое файла и попадание в папку Drive |
| 2.8 | Конвертация PDF | `convert_docx_to_pdf` локально и через Google, сравнить результат |

Результаты этого уровня фиксируются в `docs/qa/smoke_test.md`, там уже есть таблица для заполнения.

## 6. Деплой

Целевой сервер сменился. Актуальная схема описана в `docs/migration_runbook.md`.

- сервер: `169.58.83.125`, пользователь `deploy`;
- домен: `reports.projector-school.info`;
- приложение слушает `127.0.0.1:8090`, наружу его пускает системный Caddy;
- compose-файл: `docker-compose.server.yml`, без собственного reverse proxy;
- репозиторий: `proektordocs-ops/school-journal`.

Пуш в `main` автоматически запускает деплой через `.github/workflows/deploy.yml`, но только после того, как в репозитории заведены секреты и переменные.
